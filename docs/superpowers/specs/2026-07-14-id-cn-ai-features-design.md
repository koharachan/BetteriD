# BetteriD 0.0.2 中文增强与 AI 功能设计

> 日期：2026-07-14
> 实现状态：已在 `0.0.2` 交付
> 安全约束：服务端密钥不得进入前端源码、构建产物、日志或 API 响应。

## 目标

BetteriD 在 iD 编辑器的基础上，为中文 OpenStreetMap 编辑场景补充以下能力：

1. 独立维护中文翻译覆盖，同时继承上游稳定版 iD 翻译。
2. 批量生成多语言名称，并由用户在写入标签前逐项确认。
3. 按地区法定语言脚本检查主 `name`，支持在偏好中关闭。
4. 用 AI 生成 changeset comment，并提供带网页来源的 OSM 标签建议。
5. 提供多服务端提供商的任务级路由与静默回退。
6. 提供经过审核的本地照片底图和视觉标签建议。
7. 改善移动端、影像对照、室内编辑和大批量提交体验。

## 架构

```text
浏览器中的 BetteriD
  |-- 静态资源：Rust 服务托管 dist/
  |-- OSM 登录、API 和公开瓦片：同源 Rust 反向代理
  |-- 翻译、总结和标签检索：/api/osm-ai/*
  `-- 照片上传、审核和识别：/api/osm-ai/photo-*

Rust 服务
  |-- 只缓存允许公开缓存的 GET 响应
  |-- 按任务过滤 provider_order，并对上游错误执行回退
  |-- 对 AI 请求执行输入限制和按客户端 IP 限流
  |-- 对照片解码、重新编码、审核后再持久化
  `-- 通过环境变量持有所有 OAuth/AI/翻译配置
```

前端不会接收服务端 API key，也不支持在本版中保存或浏览器直连用户自定义 AI key。
这避免了 CORS 差异、浏览器存储泄露和不一致的输入安全策略。

## 提供商路由

| 任务 | 默认顺序 | 可用提供商 |
| --- | --- | --- |
| 文本、翻译、changeset comment | DeepSeek -> OpenAI -> MiMo | `deepseek`, `openai`, `mimo` |
| 带网页检索的标签建议 | OpenAI -> Kimi | `openai`, `kimi` |
| 图片审核与识别 | OpenAI -> MiMo | `openai`, `mimo` |

- 前端只提交提供商名称顺序；服务端对数量、长度、重复项和任务白名单做校验。
- 未配置的提供商会被跳过，配额、付费状态或临时上游错误不会直接暴露给前端。
- MiMo 支持配置多个 key 并顺序尝试。
- Kimi 只用于 `$web_search`，不参与通用长文本或视觉任务。
- Bing 翻译与无 key 的免费翻译路径保留为翻译回退。

## 前端功能

### 中文与多语言名称

- BetteriD 自有字符串存放在 `data/betterid_locale_overrides.json`，避免被上游翻译更新覆盖。
- `pnpm run translations` 从上游稳定发行分支继承翻译；开发者需要直接拉取 Transifex 时使用
  `pnpm run translations:dev`。
- 名称字段读取偏好中的目标语言列表，最多接受 8 个合法 BCP 47 风格语言代码。
- 翻译结果以预览列表呈现，默认不直接覆盖用户未确认的标签。

### AI 标签助手

- 仅在选择单个实体时显示。
- 请求包含用户描述、单值标签、几何类型、中心位置、界面语言和服务端提供商顺序。
- 返回值经过前后端双重归一化；`source`、`created_by`、`attribution`、`odbl`、`import`
  和 `tiger:*` 等敏感来源标签不能由助手写入。
- 建议显示置信度、理由和 HTTP(S) 来源；低置信度和删除操作默认不选中。
- 用户勾选并点击应用后才进入本地编辑历史，上传前仍需正常校验。

### Changeset 与校验

- changeset comment 可由服务端 AI 根据结构化实际变更生成，失败不阻止手动提交。
- 智能拆分支持自动、固定对象数量和按区域三种策略，并预览批次。
- `autoSafe` 只标记确定、非破坏性的校验修复；问题面板可一次应用这些修复。
- 非本地语言名称检查对混合脚本按字符占比判断，避免单个本地字符绕过提示。
- 高德来源匹配更严格，并新增天地图不兼容来源检查。

### 影像、室内与移动端

- 双影像可选择第二底图并独立调整透明度。
- 本地照片可在地图上移动、缩放和旋转；审核通过后才能显示和识别。
- 室内聚焦会保留当前建筑/楼层并弱化无关楼层和周边地图。
- WASD 提供线性 walk 与带短暂惯性的 fly 两种导航模式，表单聚焦时不截获按键。
- 移动端提供空白地图手势绘制、双击结束线、全宽侧栏和触控尺寸优化。
- 吸附范围、右键拖图、位置记忆和兼容的 JOSM 快捷键均可在偏好中调整。

### 编辑策略

在中国大陆、香港和澳门，BetteriD 阻止创建或修改军事区域及其成员实体。策略在历史动作
落栈前预览完整图差异，因此工具、快捷键、重做和动画动作使用同一检查。拦截弹窗提供转到
官方 OpenStreetMap 编辑器的链接；BetteriD 不替用户自动提交被拦截的修改。

## 照片处理与安全边界

1. 上传体、base64 解码、图像分配、像素数和单边尺寸均有限制。
2. 只接受 JPEG、PNG、WebP，并应用方向信息后重新编码为 JPEG，清除原始元数据。
3. 服务端审核通过后才将文件写入 `OSM_PHOTO_UPLOAD_DIR`。
4. 识别接口只接受本服务签发的照片 ID 或同源只读 URL，不能抓取任意外部 URL。
5. 代理部署必须明确配置 `OSM_TRUSTED_PROXY_IPS`；否则忽略转发客户端地址。
6. `/api/osm-ai/status` 只返回能力和提供商名称，不返回 key、base URL 中的凭据或完整错误正文。

## 非目标与限制

- AI 建议不是事实来源，不能替代实地知识、合法影像或 OSM Wiki。
- 本版不允许浏览器保存或直连自定义提供商密钥。
- 本地照片的公开 URL 是不可变资源；部署者负责持久化、备份和保留周期。
- 实验功能默认关闭，存储格式和交互在后续版本中可能变化。
- BetteriD 不改变 OSM 标签语义；中文只用于界面和显示，提交值仍使用规范 OSM 值。
